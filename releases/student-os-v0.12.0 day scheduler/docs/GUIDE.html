Student OS

The complete beginner's guide — what it is, why it exists, and how it works.

This guide assumes zero prior knowledge. If you have never heard of an "API", an "MCP server", or an "LLM", that's fine — every term is explained in plain words with everyday analogies, pictures, and worked examples.

One-sentence summary Student OS is a smart assistant that plugs into all the apps a student uses (github, gmail, calendar, codeforces, classroom), and every morning answers a single question — "What should I do today?" — with one clean, prioritized to-do list.

As of this version it also learns what you find important, digs deadlines out of emails, plans your day around your free time.

1. The problem: student life is scattered

A typical engineering student juggles six to eight apps every single day. No single app connects these. So the student has to open each one, read through it, and figure out what is urgent, what can wait, and what they might have missed. Things slip through.

2. The big idea: one assistant

Student OS flips the picture. Instead of the student connecting to eight apps, one assistant connects to the apps, gathers everything, sorts it by importance, and hands the student a single answer:

"What should I do today?"

3. What is "MCP"? (the key concept)

MCP — the Model Context Protocol — is a real, open standard (introduced late 2024). It defines one standard way for an AI assistant to plug into any app or data source.

Analogy: the universal plug Old laptops needed a different charger for every brand. Then USB-C arrived — one shape of plug that works with everything. MCP is USB-C for AI.

6. How one request works, step by step

1
The frontend sends a request: GET /briefing.
2
The orchestrator starts each MCP server and calls its actions.
3
Each server returns items in a common format.
4
The orchestrator merges and removes duplicates.
5
The prioritizer scores and sorts everything.
6
A summary is written and the ranked list is returned.

7. How the assistant decides what's important

The prioritizer gives every item a score from three questions:

  1. What kind of thing is it? An exam starts higher than a calendar event.
  2. How soon is it due? Due today adds a lot; no date adds nothing.
  3. What's the current context? During exam week, coursework gets a boost.

A worked example

Internship email, 2 days2.0+2.0+4.08.0high
Codeforces contest, today3.0+6.0−4.05.0medium
"Your OTP is 481920"2.0+0−3.0−1.0low

8. Why it feels fast: the cache

Gathering from 5 apps takes a few seconds (about 6). If the student refreshes the page twice in a minute, re-doing all that work is wasteful. So the assistant keeps the last result in a cache (short-term memory) for a short time and serves it instantly on repeat requests.

Analogy: leftovers Cooking a fresh meal takes time. If someone asks for the same dish two minutes later, you serve the leftovers from the fridge instead of cooking again. After a while the leftovers "expire" and you cook fresh. That expiry time is 90 seconds here. 
flowchart TD
  R["Request arrives"] --> Q{"Fresh copy
in the cache?"}
  Q -->|"Yes"| SERVE["Serve cached plan — instant"]
  Q -->|"No"| FAN["Ask all 5 servers — about 6 seconds"]
  FAN --> STORE["Store the result for 90 seconds"]
  STORE --> SERVE2["Serve the plan"]
The cache: if a recent answer exists, return it instantly; otherwise gather fresh and remember it.

The "Refresh" button on the dashboard skips the cache on purpose, so you can always force a fresh look. The proposal asked for Redis (an industrial-grade memory store) — the code uses Redis when available, and otherwise falls back to a simple built-in memory, so it works even with nothing installed.

10. A clever trick: "mock mode"

The whole system ships in mock mode: every connector returns realistic sample data. This means anyone can run the project end-to-end in seconds, with zero setup.

10. Proving it actually works (the evaluation)

Anyone can claim their assistant ranks well. We measured it. We wrote down 40 realistic student situations and, for each item, a human "how important is this today?" grade from 0 to 3. Then we compared our prioritizer against simpler methods and scored how close each came to the human grades.

In plain terms It's like grading assistants on the same test, 40 times. The "answer key" is what a sensible human would put on top. The main score, nDCG, simply measures "did you put the important things near the top?" — 1.0 is perfect, 0 is terrible.
Assistant (ranker)Average score, nDCG@5 (0–1)Verdict
Random order0.74the floor
Arrival order (no sorting)0.75barely better
Sort by due date only0.89decent, naive
Our prioritizer0.95best rule-based
Learned ranker0.97best overall

Head-to-head against the best simple method (sort-by-due-date), learned ranker won the majority of the 40 situations. The ties and losses are mostly cases where sorting by due date is already the right answer — we included those on purpose, so the test is fair.

"But could that just be luck?" Good question — and exactly what a significance test answers. The test gives a number called a p-value: the chance the result is just luck. Ours is p ≈ 2e-05 — well below the threshold of 0.05. So the improvement is genuine, not a coincidence.
Being honest about limits The 40 grades came from one author, and the scenarios are realistic but constructed. We even report the situations we lost. Saying this openly is what makes research credible.

12. What it also does now

The project kept growing one feature per version. Here's each newer capability in plain terms — every one is justified by a real student need.

🧠 It learns what matters to you (the learned ranker) A small machine-learning model learns priorities from real examples (and, over time, from what you open, finish, or dismiss). On unseen test cases it ranks even better than the hand-written rules.
📅 It finds deadlines hidden in text (NLP extraction) An email like "apply by Friday" or "submit before 3 August" used to slip through. Now the assistant reads the words and pulls the deadline out automatically.
🗓️ It plans your actual day (the scheduler) Beyond a ranked list, it builds a timetable: it fits your tasks into the free gaps around your classes. If there's more to do than hours, it schedules the most important and gently defers the rest.

15. Glossary

TermPlain meaning
APIA defined "door" one program uses to ask another program for data.
MCP (Model Context Protocol)A shared standard — a universal "plug" — that lets an AI connect to any tool the same way.
MCP serverA small program that connects one app to the assistant using MCP (the "waiter").
OrchestratorThe coordinator that talks to all the MCP servers and merges what they return.
PrioritizerThe logic that scores and sorts items so the most important is on top.
LLMA Large Language Model — an AI like Claude that understands and writes text.
OAuthThe secure "Sign in with Google" style login that grants limited, revocable access.
CacheShort-term memory that stores a recent result to answer repeat requests instantly.
TokenA secret key that proves the app is allowed to read your data (like a temporary pass).
nDCGA ranking score (0–1) that rewards putting the most important items near the top.
p-value / significantThe chance a result is just luck. A small p-value (below 0.05) means the effect is real.
Mock modeRunning on realistic fake data so the system works with no accounts or setup.
