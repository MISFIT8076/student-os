Student OS

An MCP-powered AI assistant for student life — project overview (v0.9.0)

Student OS connects all the apps a student juggles — github, gmail, calendar, codeforces, classroom — and answers one question, "What should I do today?", with a single prioritized, personalized plan. This is the whole project in one page.

1. The problem & the idea

A BTech student runs across 6–8 platforms daily; no single one connects them. Student OS becomes the one coordinator that gathers everything and hands back a single answer.

Multiple noisy inputs → one calm, prioritized answer.

2. What it does (feature highlights)

Daily briefingOne prioritized to-do list across all platforms.
Rule-based prioritizerContext-aware scoring ranks items by importance.
Smart cachingRepeat requests served instantly; Redis or in-memory.

3. How it works (architecture)

flowchart TD
  U["Student: 'What should I do today?'"]
  --> FE["Frontend (Next.js: dashboard · chat)"]
  FE -->|HTTP| API["Backend API (FastAPI)"]
  API --> ORCH["Orchestrator (tool router + cache)"]
  ORCH --> SV["5 MCP servers: GitHub · Gmail · Calendar · Codeforces · Classroom"]
  SV -->|real APIs / mock| EXT["External services"]
  SV --> RANK["Prioritizer (context-aware ranking)"]
  RANK --> LLM["LLM writer / rule-based fallback"]
  LLM --> API
Each platform is an independent MCP server; the orchestrator fans out, ranks, and plans.

Everything degrades gracefully: no accounts → realistic mock data; no AI key → rule-based writer; no Redis/DB → in-memory. So it always runs, even with zero setup.

6. How to run it (no accounts needed)

# Backend — prints today's ranked plan
cd backend
python -m venv .venv && source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -r requirements.txt
python demo.py

# Web app (separate terminal)
cd frontend && npm install && npm run dev            # http://localhost:3000

It runs in mock mode by default (realistic sample data). Connect real platforms later via docs/SETUP.md.
